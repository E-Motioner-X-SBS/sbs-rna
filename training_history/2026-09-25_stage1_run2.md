**Live.** Updated as it goes; the last section is the running log reading.

Same weights as run 1 (resumed at step 10,750 / 1.569B tokens), every other

## What changed, and why

| | run 1 | run 2 | because |
|---|---|---|---|
| token budget | 4e9 | **8e9** | 4e9 was 0.37 of one epoch. The corpus is 40.3M sequences / 10.94B usable tokens; 325.7M active parameters want ~6.5B by Chinchilla. 8e9 is 0.73 epochs, 25 tok/param. |
| recycle depth | 2, fixed | **1–3, sampled** | The model was usable at exactly the depth it saw: 1.6632 bits at 2, 2.0064 at 8. Uniform 1–3 has mean 2.0 and costs `6+2(2−1)=8` FLOPs/param/token — **identical** to a fixed 2. |
| `n_loops` in the config | 8 (advertised 144 effective layers) | **3 (54)** | 144 was a number no checkpoint could deliver. |
| shard reading | one at a time | **interleave 8** | A pool was 0.54 of one length-sorted shard, TV distance 0.342 from the corpus. Interleaving 8 gives 0.112. |
| `max_batch` | 512 | **2048** | 512 bound on the sequence *count*: 92.5% of batches capped on short shards, 83,899 real tokens/step against 194,607. |
| held-out sample | one shard, mean 185 nt | **stratified to the corpus histogram**, mean 324 nt | The old one was 52.7% 20–79 nt against a corpus 6.5% and overstated the model by ~0.19 bits. |
| chemistry dim 13 | identically zero | **live, 8.48% of residues** | `shifted_pka` had never been passed `True` by anything but a unit test. Now: a residue in a non-canonical (Leontis-Westhof 2–12) base pair carries a shifted pKa. Fires in stage 5 only, where structure is known. |
| telemetry | `bal` only | `bal`, `dead`, `w` (routing width), `btok`, both LRs | Everything else was computed and dropped at the call site. |

## First reading

```
step 10800  ce 1.2805 (1.847 bits)  bal 0.404  dead 0.0%  w 9.9/393
            btok 120,070  lr 5.54e-04/1.85e-02  acc 0.3933  15.9k tok/s  MFU 18.2%
```

- **MFU 18.2% against run 1's 13.9%** — a 31% throughput gain, from `max_batch`
  and interleaving, before any other effect. At this rate 8B tokens is ~110 h
  rather than the 143 h the old throughput implied.
- `w 9.9/393` is nucleus routing's width per step, visible for the first time:
  a token fires ~10 experts on average and the widest fires 393 of 512.
- `bal 0.404` is **double run 1's 0.19** and is the one thing on the watch list.
  Expected while the router rebuilds moments from scratch — the optimiser state
  could not be carried across because heads 9/10 changed the parameter set —
  but if it does not fall back toward 0.2 it means routing is concentrating.
- `lr 5.54e-04` is back up from run 1's 4.24e-04 because the cosine now runs
  over 8B tokens and 1.575B is 20% of it rather than 39%.
